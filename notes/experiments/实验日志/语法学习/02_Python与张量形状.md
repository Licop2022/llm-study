# 第 2 课：对照本轮代码学 Python 与形状

学习顺序：先看变量、字典、函数和切片，再看两组循环，最后读矩阵求解。以下小例子是教学算例，不是新的实验结果。

## 1. 变量、字典与解包

```python
data = {'boundaries': [1050, 1200, 1500]}
train_end, val_end, total = map(int, data['boundaries'])
```

- `=` 把右边的结果绑定到左边变量，不是数学上的恒等断言；比较是否相等用 `==`。
- `{...}` 在这里建立字典；`'boundaries'` 是字符串键。
- `data['boundaries']` 按键取值，得到三个边界。
- `map(int, ...)` 将每个值转为整数，再依次赋给三个变量，这叫解包。
- 代码有时用 `_` 接收不用的值。`_` 仍是普通变量，只是约定表示暂时不用。

源码位置：[验证指标函数](<E:/张量分解/gpu_start/d2_cell_rank_ablation.py:22>)。

## 2. 函数与参数

```python
def validation_metrics(prediction, data, history=25, horizon=5):
    ...
```

`def` 定义函数；括号内是形参；冒号后通过缩进标明函数体。`history=25` 是默认参数。定义函数不会立即计算，调用 `validation_metrics(prediction, data)` 才执行函数体；`return` 把计算结果交回调用者。

函数里的 `raise ValueError(...)` 表示条件不符合预期时明确停止，防止带着错误形状继续计算。它不是“模型预测不准确”的评价。

## 3. 先写形状，再读切片

完整数据 `X_norm.shape = (25, 100, 3, 1500)`：

| 轴 | 含义 | 索引示例 |
|---|---|---|
| 0 | 电池 | 第 0 个电池 |
| 1 | 循环内采样点 | 第 0 到 99 个位置 |
| 2 | 指标 | 0 电流、1 电压、2 容量 |
| 3 | 循环 | 第 0 到 1499 个循环索引 |

```python
capacity = data['X_norm'][:, :, 2, 1050:1200]
```

两个 `:` 保留全部电池和采样点；整数 `2` 选容量并去掉指标轴；`1050:1200` 包含 1050、不包含 1200。因此结果形状是 `(25, 100, 150)`。

`shape[:2]` 取形状元组的前两个值 `(25,100)`。`(*shape[:2],150)` 用 `*` 解包，得到 `(25,100,150)`。不要将这里的 `*` 和数组逐元素乘法混为一谈。

## 4. 布尔掩码与误差

```python
error = (prediction - target).astype(np.float64) * scale
rmse = np.sqrt(np.mean(error[mask] ** 2))
```

- `astype(np.float64)` 将误差转换为双精度后统计；不表示模型本身改成双精度训练。
- `scale` 把 min-max 坐标中的误差恢复为容量 mAh；预测减真实时偏移已经抵消。
- `mask` 是布尔数组。`error[mask]` 只取 True 的位置，形成一维选中值数组。
- `**2` 是平方；先均值、再开方得到 RMSE。`^` 在 Python 中不是乘方。
- 数组掩码的逐元素“且”用 `&`，例如 `available & ~observed`。`~` 对布尔数组取反；不能用处理单个布尔条件的 `and` 代替。

隐藏点误差只用来评估，不可被拿去构造本轮仅观测核推断的输入。

## 5. 两组实验是怎样启动的

```python
for rank in (12, 25):
    name = f'refit_M{rank}'
```

`(12,25)` 是包含两个值的元组。循环执行两次，先让 `rank=12`，再让 `rank=25`；不是从 12 一直跑到 25。缩进内代码是每轮要做的事。

`f'...'` 是 f-string，会把花括号里的表达式替换为其值；依次生成 `refit_M12` 和 `refit_M25`。

源码位置：[两组训练的循环](<E:/张量分解/gpu_start/d2_cell_rank_ablation.py:133>)。

| 对象 | M=12 | M=25 |
|---|---|---|
| A | `(25,12)` | `(25,25)` |
| B | `(100,50)` | `(100,50)` |
| 训练核 G | `(12,50,3,1050)` | `(25,50,3,1050)` |
| 单循环容量核 | `(12,50)` | `(25,50)` |

M=25 允许保留更多电池方向，实际是否保持满秩还要看输出中的有效因子秩。

## 6. `with` 与文件格式

```python
with np.load(path, allow_pickle=False) as archive:
    a = archive['U1']
    b = archive['U2']
```

`with` 在进入与离开代码块时管理资源；这里离开代码块会关闭 `.npz` 归档句柄。已经取出的数组仍可使用。`.npz` 可以保存多个有名字的 NumPy 数组；`.npy` 通常保存一个数组；`.json` 在本项目保存可读的配置与指标摘要。

`Path` 对象的 `/` 用于拼接路径，例如 `checkpoint_dir / 'summary.json'`，不是在做数值除法。不同对象类型可以赋予相同符号不同含义。

## 7. 再看矩阵计算：设计矩阵

源码位置：[验证核推断](<E:/张量分解/gpu_start/d2_cell_rank_ablation.py:53>)。

```python
design = torch.einsum('im,jn->ijmn', a, b).reshape(25 * 100, -1)
```

`i` 对应电池，`j` 对应采样点，`m/n` 对应两个潜在方向。这里没有求和消去下标，而是形成每个 `A[i,m] * B[j,n]`，结果形状 `(25,100,M,50)`。

`reshape(2500,-1)` 把两组轴分别合并；`-1` 表示由元素总数自动推算。设计矩阵形状是 `(2500,600)` 或 `(2500,1250)`。这样一个循环的容量观测可以写成设计矩阵乘展开后的容量核。

`reshape` 不会神奇地重排轴。转置与 reshape 的顺序决定每个数字对应哪个电池、采样点、方向；这也是需要独立形状与数值检查的原因。

## 8. `@`、逐元素乘法与批量求解

```python
lhs = design.T @ (design[None] * weights_t[:, :, None]) + eye
rhs = y @ design
coefficients = torch.linalg.solve(lhs, rhs.unsqueeze(-1)).squeeze(-1)
```

- `.T` 是这里二维矩阵的转置。
- `@` 表示矩阵乘法；`*` 在这里表示逐元素乘法。
- `None` 索引插入长度为 1 的轴，使权重能广播到设计矩阵每一列。
- `eye` 是 ridge 系数乘单位矩阵，不是所有元素都相同的矩阵。
- 本段执行前，未观测位置的 `y` 已被 `torch.where` 置零，所以 `rhs` 不会读取隐藏值作输入。
- `unsqueeze(-1)` 添加最后一个长度为 1 的轴；`squeeze(-1)` 再移除该轴。
- `torch.linalg.solve(lhs,rhs)` 求线性方程，不需要先显式计算矩阵逆。

本轮一批 b 个循环时，`lhs` 形状为 `(b,M*50,M*50)`，右侧形状为 `(b,M*50,1)`；b 最多 4，最后一批可能不足 4。每个循环独立求核，A/B 固定。

## 9. 三种“验证”要分清

| 名称 | 数据来自哪里 | 用途 |
|---|---|---|
| 数据协议 PASS | 重新准备的数据与已有输入 | 检查掩码、缩放及数值一致 |
| 训练中的 `val_RMSE` | 训练时间前缀内留出元素 | 选择参数检查点 |
| 最后验证容量指标 | 后续时间验证循环 | 比较两组同周期重建效果 |

本轮最后一项仍会使用当前验证循环自己的观测推断核，所以不是未来预测。未来预测要求模型在预测起点只读取更早循环。
