# 第 1 课：读懂本轮终端命令

本课对应你实际下发的秩消融命令。示例是教学材料，不代表你已经掌握；先读懂，再在网页写自己的复盘。

## 1. 先分清在哪台机器

| 看到的提示符 | 所在位置 | 通常在这里做什么 |
|---|---|---|
| `PS C:\Users\24980>` | 电脑 Windows PowerShell | 上传文件、发起 SSH 登录 |
| `niehaoxian@siton-server:...$` | 服务器 Linux | 激活环境、运行代码、读日志 |
| `>>>` | Python 交互解释器 | 逐句执行 Python 语句 |

`PS ...>`、末尾的 `$` 和 `>>>` 都是提示符，不用复制。代码里的 `.py` 文件在服务器上由 Python 执行，不是把整份 Python 源码粘贴进 Linux shell。

## 2. 把完整命令拆开读

下面是本轮已下发的命令，供阅读；程序正在运行时不要重复启动。

```bash
CUDA_VISIBLE_DEVICES=4 python -u d2_cell_rank_ablation.py --inputs runs/forecast_inputs_20261017T091733_622696Z/forecast_data.npz --device cuda:0 2>&1 | tee -a cell_rank_ablation_20261018.log
```

| 片段 | 在本轮的含义 |
|---|---|
| `CUDA_VISIBLE_DEVICES=4` | 给这次启动的程序设置环境变量，使其看到指定的物理卡 4 |
| `python` | 使用当前环境的 Python 解释器 |
| `-u` | 让 Python 标准输出/错误输出不缓冲，便于及时看日志；不是 GPU 加速选项 |
| `d2_cell_rank_ablation.py` | 要执行的脚本，相对当前服务器目录寻找 |
| `--inputs ...npz` | 向脚本传入已有预测输入文件的路径 |
| `--device cuda:0` | 告诉脚本使用其可见设备中的逻辑 GPU 0 |
| `2>&1` | 将标准错误流 2 合并到标准输出流 1 |
| `|` | 管道：把前面命令的输出交给后面命令 |
| `tee` | 同时把收到的输出显示在终端、写入文件 |
| `-a` | 追加日志，不清空原文件；重跑时日志里可能有多次运行 |

本轮只暴露物理卡 4 时，它通常被程序编号为 `cuda:0`。设备编号是两层映射，不应把 `--device cuda:4` 机械地照搬成物理卡编号。实验室若采用调度分配，应以实际分配为准。

环境变量前缀 `NAME=value command` 是 Linux shell 语法；Windows PowerShell 设置环境变量用另一套语法，不可直接互换。

## 3. 路径、引号与环境

```bash
source "$HOME/venvs/tensor-soh/bin/activate"
cd "$HOME/tensor_projects/tensor_soh_start"
```

- `$HOME` 是服务器用户的主目录，本例为 `/home/niehaoxian`。
- 双引号允许展开 `$HOME`，并把整个路径作为一个参数处理。
- `source` 在当前 shell 中执行激活脚本，使后续 `python` 使用该环境；不代表重新安装软件。
- `cd` 改变当前工作目录。
- `runs/xxx/forecast_data.npz` 是相对路径，从当前目录往下找。
- `/home/niehaoxian/...` 是 Linux 绝对路径；`E:\张量分解\...` 属于 Windows，本例服务器不会直接识别为本机文件。

## 4. `--参数` 怎样变成 Python 里的值

脚本里有：

```python
parser.add_argument('--steps', type=int, default=1500)
parser.add_argument('--batch', type=int, default=4)
args = parser.parse_args()
```

`argparse` 读取命令行参数。`type=int` 要求整数，`default=1500` 表示没有显式传入时用 1500。`args.steps` 是解析后的更新次数。

本轮没有显式写 `--steps`，因此按当前代码默认每组 1500 次更新；最终仍应核对运行 summary。

**本轮 `--batch 4` 控制的是验证阶段一次解几个循环的 ridge 核，不是 Transformer 的训练 batch，也不是每组只训练 4 次。** 模块一当前每次更新使用整个训练张量的观测损失。

## 5. 阅读日志时先找哪些行

| 输出 | 说明 |
|---|---|
| `PASS: training masks...` | 已有输入和重新准备的数据协议一致 |
| `FITTING M=12` / `FITTING M=25` | 开始对应组训练 |
| `step ... train_RMSE ... val_RMSE` | 当前更新步与前缀内留出元素误差 |
| `VALIDATION SUMMARY` | 两组训练和验证推断后打印的最终对照 |
| `Saved:` | 运行产物保存位置 |

单独看到 PASS 或创建了结果目录，都不能判定整次实验完成。经过 `tee` 管道后，shell 默认返回值通常来自最后一个命令；也不能只凭管道结束时的返回值认定 Python 成功，要核对最终输出和产物。

## 先自答，再看参考

1. 物理卡 4 为什么配 `cuda:0`？
2. `-u` 会不会让 GPU 算得更快？
3. 日志中的 `val_RMSE` 和最后时间验证集的 SOH MAE 是同一件事吗？
4. `tee -a` 在第二次执行时会怎样处理旧日志？

### 参考答案

1. 程序只看到筛选后的设备，逻辑编号从 0 开始。
2. 它改变输出缓冲，不改变模型计算速度。
3. 不同。前者用于训练前缀内留出元素的检查点选择；后者评估后续时间循环的容量峰值重建。
4. 继续追加，应结合每次输出的运行路径区分多次执行。
